## 持久化分次运行

```powershell
.\.venv\Scripts\python.exe examples/13_persistence.py start --thread homework-1
.\.venv\Scripts\python.exe examples/13_persistence.py resume --thread homework-1
.\.venv\Scripts\python.exe examples/13_persistence.py show --thread homework-1
```

第一条运行完可以关闭 PowerShell，再打开并进入同一目录运行第二条。恢复时只执行审批和查询，不重新生成 SQL。第二条等待你输入 yes 或 no。再次从头演示请将三条命令的 thread 都改成新的名称，例如 homework-2。数据库保存在项目 data/checkpoints.sqlite。

## 批量验证与上传

`python run_advanced.py` 批量运行新增八项，以明确打印的命令行测试输入验证审批；不是等待真实人工。`python run_all.py` 运行全部17项。请用本项目虚拟环境中的 python 执行。日志存于 runs/。

`python -m unittest discover -p "test_*.py"` 运行全部单元测试。测试使用替身模型检查分支与边界；示例程序始终请求真实千问，接口失败会报错。

新电脑执行 `uv sync --locked` 安装依赖；复制 .env.example 为 .env 并配置密钥。GitHub 不上传 .env、.venv 或 data/。本机文件和可配置缓存继续使用 D 盘。

## 实现说明

- 审批用 interrupt 和 Command(resume=...)；生成节点与审批节点分离，恢复不会重复请求模型。
- MemorySaver/InMemorySaver 只存内存，SQLite 才能跨进程恢复。get_state_history 按最新到最早显示。
- 普通字符串/字典列表使用 operator.add 合并；add_messages 专用于聊天消息。
- 循环可能第一次就合格，不能为截图伪造重试；单元测试另验证重试和达到上限。
- 客服最多首次处理加2次重试，最后一次合格仍成功；模型自检不是用户真实满意度。
- 投诉并行分支全部完成后才检查质量；重试不重复生成本地工单和通知草稿。
- 主管通知仅生成待发送草稿，工单和转人工是本地作业记录，不接真实商家业务系统。
- SQL 在隔离的内存教学数据库真实执行，数据库授权器拒绝写入和删除等操作。
