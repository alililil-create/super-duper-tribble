# 语境：文章驱动英语学习助手

阶段 0–3 课程实现，覆盖图片中的基础环境、后端、前端、数据库会话、登录注册、文章/场景接口、数据调用流程，以及学习会话和对话。

项目结构：`backend-fastapi/`（API、ORM、千问服务与测试），`frontend/`（Vue 3 页面），`docs/`（作业说明），`evidence/`（真实运行结果）。

## 启动

本机项目位于 `D:\Codex\2026-10-20\learn-assistant`。按根目录 `截图命令.txt` 分别启动后端、前端、验收脚本。

换一台电脑：安装 Python 3.11+、Node 22、pnpm、uv、MySQL 8。在后端运行 `uv sync --locked`，复制 `.env.example` 为 `.env` 并填写数据库、随机 JWT 密钥和千问密钥；前端运行 `pnpm install --frozen-lockfile`。前端 `.npmrc` 将缓存定向到 D 盘，其他电脑可按实际盘符调整。数据库需预先创建，应用启动时创建缺失表。

浏览器访问 http://127.0.0.1:5173，Swagger 访问 http://127.0.0.1:8000/docs。注册自己的账号后，添加文章 → 生成场景 → 查询已有场景 → 进入学习会话 → 发送英文消息。每个浏览器标签的 token 保存在 sessionStorage，可用不同标签验证两个用户。

## 设计与范围

- MySQL 8 + SQLAlchemy 异步会话。每个请求独立会话，连接池 10+20。
- bcrypt 密码哈希、带过期时间的 JWT、登录保护。密码最多 72 个 UTF-8 字节，避免 bcrypt 截断。
- 文章/场景按阶段 2 正文规则共享；学习会话与消息按 user_id 隔离。用户无法读取其他人的会话。
- 场景真实调用 Qwen JSON Mode，Pydantic 校验失败重试一次，失败不入库。
- 聊天读取最近 10 条消息，当前消息只出现一次；千问失败仍保留已提交的用户消息。
- 单进程课堂运行。同会话的重叠请求返回 409；多进程生产部署需分布式锁、速率限制、迁移与 HTTPS 等进一步配置。
- 不自动执行讲义中的系统修改命令，不删除旧数据库；本项目使用独立数据库。

## 验证

后端：`uv run pytest -q`（SQLite 隔离测试，千问使用明确的测试替身，仅验证逻辑）。

前端：`pnpm build`（TypeScript 检查与生产构建）。

真实验收：启动后端后执行 `uv run python scripts/demo_online.py`，实际访问 MySQL 和 Qwen，成功才写入 `evidence/online-run.txt`。测试替身不会用于网页或在线演示。
